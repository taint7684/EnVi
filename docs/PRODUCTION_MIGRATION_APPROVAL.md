### How to run

1. Open Supabase SQL Editor
2. Copy entire content of `db/migrations/production_v2_combined.sql`
3. Paste and click "Run"
4. The script runs as a single transaction (`begin; ... commit;`)
5. If any statement fails, the entire transaction rolls back — nothing is applied

### Mid-failure handling

If the script fails:
1. Note the last `-- ✅ APPLIED: XXXX` comment before the error message
2. Run the DIAGNOSTIC QUERIES (§A at the bottom of the SQL file) to see which objects were created
3. Since all migrations use `IF NOT EXISTS` (idempotent), fix the issue and re-run the ENTIRE script
4. Already-applied parts are skipped; only the failed part and subsequent parts run

## 6. Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Migration fails mid-way | Low | Medium | Transaction rollback; restore from backup |
| Data loss | Very low | High | All migrations use `IF NOT EXISTS`; no `DROP` or `DELETE` on existing data |
| RLS misconfiguration | Very low | Medium | All new tables have RLS enabled + policies; verified 50/50 |
| `delete_my_account` breaks | Low | High | Function progressively updated; tested on QA (PASS) |
| Vercel deploy fails | Low | Low | Redeploy from Dashboard; previous deployment stays live |

**No destructive operations** in the migration: no `DROP TABLE`, no `TRUNCATE`, no `DELETE FROM` on existing data. Only `CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, and `CREATE OR REPLACE FUNCTION`.
